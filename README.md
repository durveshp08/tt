# Timetable Helper — AI Agent & Rule-Based Recommendation System

A free, offline-first, cross-platform timetable application powered by an intelligent rule-based AI recommendation engine. Enter any academic subjects (e.g., Maths, Science, English, History, etc.), set weekly session frequencies, and the engine automatically generates transparent, conflict-free weekly schedules.

---

## 🌟 Overview & AI Agent Architecture

This project implements an **AI Scheduling Agent** using a **Rule-Based Recommendation System**:

```
 ┌────────────────┐       ┌────────────────────────┐       ┌─────────────────────────┐
 │   PERCEIVE     │  ───> │         REASON         │  ───> │          ACT            │
 │ • User Subjects│       │ • Hard Rule Knowledge  │       │ • Conflict-Free Weekly  │
 │ • Frequencies  │       │ • Forward-Checking     │       │   Timetable Output      │
 │ • Lab Requests │       │ • Constraint Solving   │       │ • Local Persistence     │
 └────────────────┘       └────────────────────────┘       └─────────────────────────┘
```

- **Perceive:** The agent captures user input (theory subjects, weekly lecture count, two-hour lab sessions, and time-slot constraints).
- **Reason:** The inference engine evaluates candidate slots against a strict knowledge base of scheduling rules using forward checking and constraint propagation.
- **Act:** The agent outputs an optimized, conflict-free weekly timetable recommendation with complete explainability and determinism.

## ⚙️ The 8 Core Scheduling Rules (Knowledge Base)

Every timetable generated by the recommendation engine satisfies all eight constraints:

1. **Fixed Lab Blocks:** Each laboratory session requires a continuous two-period block, allocated before single theory periods.
2. **No Subject Clashes:** The same subject is never assigned more than once to the same time period across parallel groups, preventing double-bookings.
3. **Theory Rotation:** Theory lectures are systematically distributed across the week using modular round-robin arithmetic to avoid overloading any single day.
4. **Mandatory Recess & Breaks:** Daily rest periods are strictly reserved:
   - **Recess:** 11:00 AM – 11:40 AM (40 minutes)
   - **Break:** 1:40 PM – 2:00 PM (20 minutes)
5. **Lab Pairing:** Consecutive lab hours are locked together to preserve practical continuity.
6. **Slot Capacity:** Every lecture slot accommodates strictly one subject session.
7. **Weekly Balance:** Total weekly subject hours are evenly distributed across the 5 working days (Monday to Friday).
8. **Dynamic User Flexibility:** The engine dynamically adapts to any subjects (Maths, Science, English, etc.) and custom session counts entered by the user.

## 📱 Free Cross-Platform Installation Guide

The application is built to run on any smartphone, tablet, or laptop without subscription fees, app store charges, or paid developer accounts.

### 🤖 1. Android Installation

#### Option A: Progressive Web App via Chrome (Recommended — Instant & Free)
1. Open **Google Chrome** on your Android smartphone or tablet.
2. Navigate to your hosted website URL (e.g., your GitHub Pages link).
3. Wait for the page to load. An **"Add to Home screen"** prompt will appear at the bottom.
4. If the prompt does not appear, tap Chrome's **three-dot menu (⋮)** in the top-right corner.
5. Tap **"Install app"** or **"Add to Home screen"**.
6. Select **"Install"** to confirm.
7. The **Timetable Helper** app icon will appear on your home screen and in your app drawer. It launches full-screen like a native app and works completely **offline**.

#### Option B: Standalone Android APK (Free GitHub Actions Build)
1. Go to your GitHub repository and click the **Actions** tab.
2. In the left sidebar, select **Build installable Android APK**, then click **Run workflow → Run workflow**.
3. Once completed (green checkmark), click on the completed run.
4. Under **Artifacts** at the bottom, download **Faculty-Timetable-Helper-APK** (ZIP archive).
5. Extract the ZIP to obtain `app-debug.apk` and transfer it to your Android device.
6. Open the file on your device. When prompted, allow **"Install unknown apps"** and tap **Install** (if Play Protect displays a prompt, select **"Install anyway"**).
7. Open **Timetable Helper** from your device's app drawer.

### 🍏 2. iPhone & iPad (iOS) Installation

iOS does not allow direct APK downloads, but fully supports installation through Apple's native Web App standard:

1. Open **Safari** on your iPhone or iPad (must use Safari, as iOS requires it for home screen web apps).
2. Navigate to your hosted app URL.
3. Tap the **Share** button (the square icon with an upward-pointing arrow `↑` at the bottom of the screen on iPhone, or top-right on iPad).
4. Scroll down the share menu and select **"Add to Home Screen"**.
5. (Optional) Customize the app name, then tap **"Add"** in the top-right corner.
6. The app icon appears directly on your iOS Home Screen. Tap it to launch full-screen without Safari browser bars, with full **offline** support.

### 💻 3. Laptop & Desktop (Windows, macOS, Linux)

#### Option A: Standalone Desktop App (via Chrome or Microsoft Edge)
1. Open the app URL in **Google Chrome** or **Microsoft Edge**.
2. Look at the right side of the address bar for the **Install** icon (a computer monitor with a down arrow, or a `⊕` symbol). Click it.

## 🎓 Viva-Ready Defense Questions & Answers

Be prepared for project viva and evaluation questions with these concise answers:

| Question | Model Viva Answer |
| :--- | :--- |
| **Q1: Why is this system called an "AI Agent"?** | An AI agent is an entity that perceives its environment through sensors/inputs, reasons through a knowledge base, and acts through actuators/outputs. Here, the system perceives subject frequencies, reasons over scheduling rules via forward checking, and acts by recommending a conflict-free timetable. |
| **Q2: Why use a Rule-Based Recommendation System over Machine Learning?** | Academic scheduling consists of hard, non-negotiable constraints (no professor or subject double-booking, fixed lab blocks). ML models are probabilistic and can hallucinate invalid overlaps. A rule-based system guarantees 100% adherence, determinism, and explainability. |
| **Q3: How are scheduling conflicts handled?** | The engine uses forward-checking constraint satisfaction. Before assigning any subject to a slot, it verifies that the subject has not already been assigned to that day/slot and that capacity exists. If a violation is detected, the candidate is rejected and alternative slots are evaluated. |
| **Q4: Can this schedule any subjects?** | Yes. The engine is completely domain-agnostic. Whether configured for basic school subjects (Maths, Science, English, etc.) or university modules, the system dynamically accepts any subject names and session quotas. |
| **Q5: Why choose a PWA over a native App Store app?** | A Progressive Web App allows universal distribution across Android, iOS, Windows, Mac, and Linux from a single clean codebase. It eliminates developer account costs, app store approval delays, and storage overhead while still providing offline capabilities and home-screen launching. |
| **Q6: What are the daily time slots?** | 8 distinct periods: 9:00–10:00, 10:00–11:00, 11:00–11:40 (*Recess*), 11:40–12:40, 12:40–1:40, 1:40–2:00 (*Break*), 2:00–3:00, and 3:00–4:00. |
